Logging now implemented
scripts/telemetry.py runs read-only on the HOST, with no Docker or sudo required.
Sample once per second, starting before model startup and continuing through
warmup, timed requests and cooldown. JSONL is line-flushed. UTC and monotonic
timestamps permit alignment with request events on the same host. metadata.json
records boot ID, CPU policy settings, GPU XML inventory, commit and dirty state.
Keep model names/revisions, image digest, exact launch flags, job ID, prompt hash,
room temperature and physical airflow arrangement in each campaign manifest.

Normal versus efficiency experiment
Define efficiency80 as an 80% MAXIMUM CLOCK policy, not 80% power or throughput.
Use hardware CPU policy maxima and the GPU's reported maximum clock as explicit
references, and record normal observed loaded clocks for interpretation.
Observed initial references: GPU max SM 3003MHz -> target <=2402MHz; E CPU
2808000kHz ->2246400kHz; P CPU3900000kHz ->3120000kHz. Driver rounding may apply.
Keep governors, memory clocks, CPU quota, model flags, prompts, contexts and
concurrency identical. CPU frequency control is not the queue's 16-CPU quota.
GPU wattage limits are N/A: do not use nvidia-smi -pl as a power-cap recipe.
Proposed GPU control: nvidia-smi -lgc 0,2402; reset: nvidia-smi -rgc.
CPU control: scaling_max_freq per policy, preserving min <= max.
These controls have NOT been applied or validated under load in this session.
The GPU may normally sustain ~2400MHz anyway: 80% of advertised max might have
little effect. Report that honestly; an additional lower cap needs a separately
named experiment rather than silently changing the meaning of efficiency80.

Control lifecycle required before experiments
Host caps affect every process. Reserve an otherwise idle machine/queue, snapshot
all CPU min/max/governor values and establish the GPU's pre-existing lock state.
Do not overwrite unknown pre-existing GPU locks; resetting them is not restoration.
Run normal and capped GPU/CPU qualification loads through compute-job, verify
observed clocks obey caps, and monitor perf/temperature; an accepted command alone
is not proof. Restore original CPU limits and established GPU baseline in finally
and on signals; verify readback. Persist rollback instructions before applying.
No permanent service or firmware changes needed. Do not bypass queue controls.

Comparison design
1. Qualify telemetry and hardware health, then each model's coherence/tool parser.
2. Separate cold startup/JIT time and peak RAM from warmed inference measurements.
3. Start normal/capped trials at comparable hottest-zone temps (target within2C);
   hold ambient/airflow constant and record fan hysteresis. Do not equate idle
   GPU SW Power Cap flag with a hardware fault; inspect deltas and loaded behavior.
4. Same fixed prompts, seeds, thinking budget, output limit, quant, drafter and
   runtime within each model's A/B. Measure c1, c2, c4; actual aggregate and per-
   request speed, TTFT,p50/p95,total task time and correctness. Small pilot samples
   do not support stable p95; retain every request and report sample counts.
5. Include short and long cold-prefill workloads, warm-prefix agent turns,
   code vs prose and sustained finite load. Repeat>=3 paired runs, alternating
   AB/BA order to reduce warmup/thermal bias. Quality runs also repeat when needed.
6. Report throughput retained, time/task, peak hottest-zone temperature,
   fan RPM, peak RAM, GPU-reported joules/task and tokens/joule with coverage.
   Lower watts but longer runs can consume more energy. No whole-system energy
   claim without wall measurement. No extrapolation from short idle sampling.

Stop policy
Logger only raises thermal_alarm at90C; it DOES NOT cancel or throttle anything.
Before sustained load, add a tested queue-aware watchdog tied only to our job ID:
cancel on hottest zone>=95C, sustained host MemAvailable<8GiB, or sensor loss.
Record reason, cancel result, and cooldown. Never terminate another user's job.
Thresholds are conservative experiment boundaries, not manufacturer guarantees.
