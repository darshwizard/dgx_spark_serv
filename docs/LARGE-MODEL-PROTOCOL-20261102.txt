Before releasing each phase, wait at least 30 seconds; target <=60 C hottest
sensor, with a five-minute wait limit. Record actual starting temperature and
whether that target was reached. This is not proof of identical thermal state.

Normal = default CPU/GPU clock limits, 20 CPU quota. Capped = 80% hardware-max
CPU clock limits plus a GPU SM ceiling at 80% of reported maximum; same 20 CPU
quota. Record actual clocks. GPU normally runs below its maximum, so the GPU
ceiling may have little effect. This is a frequency-cap experiment, not a
claim of 20% less power or 20% less throughput.

Temporary job backstop: 118 GiB charged-memory limit, no anonymous job swap,
16 GiB shared memory. GPU allocations on this shared-memory platform are not
fully represented in the cgroup charge, so host memory pressure is primary.
Root watchdog outside the job cgroup samples every 100 ms and cancels only our
job at hottest ACPI >=90 C, host available memory <2 GiB, host swap growth
>64 MiB together with <4 GiB available, required sensor loss, or controller loss. Phase admission needs >=3 GiB
available. An in-job guard backs it up. Restore original runtime, limits, public
reference pages and clock ceilings after the experiment, including failures.
Firmware, EC, automatic fan control and host swap configuration stay unchanged.

Interpretation
Report quality scores/failures, prefill/decode and aggregate concurrency speed,
wall duration, temperature, both fan RPMs, memory minima, actual clocks and
approximate GPU-reported joules per completed workload. Integrate only intervals
covered by power samples; report gaps. Exclude profile transitions and cooldowns
from workload energy; report startup separately. These are GPU rail estimates,
not wall/system energy. No whole-machine efficiency winner without a wall meter.
