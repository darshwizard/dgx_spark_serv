Thermals and control
Full successful Qwen campaign peak ACPI sensor: 82.8C.
Peak after caps applied: 80.4C (includes end-of-run cooldown).
Minimum host available RAM: 44.59GiB.
No90C guard aborts or cgroup memory-limit events. GPU-reported power is not wall
power. Ambient was not measured. Startup/autotuning, quality, normal throughput,
and capped throughput are distinguishable in logs but not matched thermal trials.
One server stayed loaded for quality and both throughput matrices; no reload
between clock profiles. Caps: CPU2.2464/3.120GHz; GPU maximum2.402GHz. Actual
observed clocks are in telemetry. All CPU limits/default GPU clocks and original
queue runtime/reference files restored with readback checks after completion.
This one normal-then-capped pass uses unpaired random corpus offsets; it cannot
establish a causal efficiency gain, even where temperatures/rates differ.

Recipe and compatibility
Qwen target: nvidia/Qwen3.8-27B-NVFP4, DFlash2: z-lab/Qwen3.8-27B-DFlash2.
Exact revisions in model-manifest.json. The NVIDIA128GB Spark playbook recipe
uses NGC26.10.pre1, dynamicNVFP4 kernels, FP8KV, DFlash2 with7drafttokens, qwen3
reasoning and qwen3_xml tools. Our serving flags are saved in launch.json.
Shared adaptations for queue/comparison: context32768,max4sequences,util0.55,
16CPU/96GiB/4GiBshm,OMP8,offlineweights/corpus,read-onlyroot,loopbackAPI.
The first startup failed in vision flash-attention with unsupported PTX toolchain
on hostdriver580.178.04; preserved as qwen-standard-01. No driver was changed.
Retry uses supported --language-model-only, which skips the failing vision
encoder. Therefore this validates TEXT serving only, not multimodal support.
Startup also did kernel compilation and autotuning; timings are separate from
benchmarked throughput. Keep performance warnings and first-use latency caveats.

Reproduce
Build the included Dockerfile with the same upstream harness checkout directories
and commits in spec.json (pip --no-deps preserves the base's serving dependencies).
Download/stage model snapshots per model-manifest.json. Stage scripts/qwen_job.py
and qwen_standard.py as /workspace/code. Use the queue spec with a unique run ID.
Keep the corpus cache from the Bolt experiment under /workspace/.cache/llama-benchy.
Run host telemetry; the wrapper first runs quality, then normal throughput, then
writes bench/ready-for-cap. An owner controller on the reserved host applies and
verifies caps and writes bench/cap-applied. Always restore caps/runtime in finally.
No vision, firmware, EC, or fan-setting changes are part of this experiment.
Raw JSONL/server logs are gzip-compressed. Full quality report and per-repetition
throughput JSON remain readable under experiments/qwen-standard-20261102/.
